# 兼容范围

基准：Java SDK 3.3.7，官方 C++ 3.3.7.0，源提交记录在 upstream.lock.json。Java JAR 的构建提交可能不同；比较版本、公共行为及交叉解码，不假定构建元数据相同。

- 810 个业务签名包含重载；不包含 Java 构造器、内部 JNI/SWIG 辅助类和 Bean getter/setter。54 个模块、734 个 Bean、41 个枚举、379 个回调类型已生成。
- 保留 Java 业务方法名、参数顺序、DTO 字段、回调顺序。Java long 使用 bigint；只接受不丢精度的 number。Java byte[] 对应 Buffer/Uint8Array。
- Node 不复制 Java 的线程和异常类型。原生回调经 Node-API 事件循环交付；用户回调抛异常走 Node uncaughtException 通道，应用应自行处理。
- 一个进程一个 SDK owner，不支持 worker_threads。多个 Node 子进程各自建立连接，不共享实例。
- 取消监听抑制已经排队的回调；关闭 SDK 后旧句柄失效。生命周期转换（initialize/shutdown）是同步调用，可能阻塞事件循环。
- 取消监听和 shutdown 不撤销已发送的业务指令。控制权释放、DRC 断开等应在关闭前按业务顺序执行并确认结果；不能用“没有回调”推断设备操作没有发生。
- 通知连接成功后再创建设备实例。官方实现可能在通知未连接时遗漏业务订阅。waitForNotificationConnection 默认等待 15 秒，超时抛错。
- 订阅队列每个回调最多 256 条；视频帧排队载荷跨回调共用 64 MiB 上限。超过上限丢弃新事件，droppedCallbacks 累计增加。queuedFrameBytes 仅统计复制到绑定队列的帧字节，不是整个进程内存。
- LiveModule 空帧或大于 10 MiB 的帧按官方 Java 规则过滤；PullStreamModule 保留空帧语义，仍受总载荷限制。消费者须及时处理，不在回调中执行耗时阻塞任务。
- 普通查询、通知不都依赖 DRTC，但当前整体产物仍限定 Linux x64/glibc。不能只删掉 libdrtc/libdrpc 就得到 Windows 原生 SDK。

## 原生崩溃与进程隔离

**P1：原生代码与 Node 在同一进程。** 绑定、官方 C++ 核心或闭源库的段错误、`abort` 等致命错误可能使整个 Node 进程退出。JavaScript `try/catch`、Promise 拒绝处理或 `uncaughtException` 不能可靠恢复这种故障。

生产集成应将 SDK 放在独立 OS 进程/服务或容器中，经 RPC/IPC 与主业务后台通信。为该进程配置健康检查、带退避的重启、重新初始化和订阅恢复。`worker_threads` 共享进程且本绑定不支持，不能实现这种隔离。当前 Skeleton Demo 直接在 HTTP 后台进程内加载 SDK，尚未实现独立进程代理。

进程退出可能发生在设备已经执行指令、结果尚未交付之间。恢复后应查询设备/任务状态或使用业务幂等机制确认结果，不能自动重发所有在途控制指令。隔离限制故障影响范围，不修复底层崩溃，也不保证实时数据不会中断。

## 回调队列与数据丢失

**P1：回调是尽力交付通道，不保证无损。** 原生线程以非阻塞方式向 Node 事件循环投递；每个连续监听回调最多积压 256 条，一次性回调队列上限为 1。所有视频回调共用 64 MiB 的待交付帧载荷预算，复制帧前预留空间。队列或载荷预算不足时，丢弃当前新事件/新帧，已有队列继续交付；没有自动重传、落盘、补齐或向上游施加背压。

`getDiagnostics()` 可观察以下进程级指标（类型为 `bigint`，JSON 序列化需转换）：

| 字段 | 含义及限制 |
|---|---|
| `droppedCallbacks` | 本进程累计丢弃次数，包含投递队列满、帧载荷预算不足和帧内存分配失败；SDK shutdown 后不清零。监测时使用差值，进程重启则重新建立基线。 |
| `queuedFrameBytes` | 当前排队帧载荷字节数，不含全部事件、对象和原生库内存，不能当作整个进程内存用量。 |
| `maxQueuedFrameBytes` | 绑定的帧载荷预算，目前为 64 MiB。 |

计数为 0 **不证明数据完整**：上游网络丢失、取消/关闭时按设计抑制的回调，以及 LiveModule 按 Java 规则过滤的空帧或大于 10 MiB 的帧，不计入该指标。它也不提供逐订阅丢失明细。

保持回调轻量，避免同步磁盘操作、复杂计算和其他事件循环阻塞；按实际处理能力降低订阅量或数据频率，并监测丢弃增量、队列占用和事件循环延迟。将工作转移到应用队列时也必须定义容量及溢出策略。对状态类数据可在支持的接口上定期查询并对账；已经丢失的历史事件和视频帧不能依靠当前状态查询补回。无损审计或安全关键场景必须另设可靠的数据来源和确认机制。

## 官方源码的三处私有构建补丁

scripts/patch-staged-sdk.mjs 明确检查原代码形状，版本不匹配时失败。DroneImpl 先销毁业务模块/管理器，再销毁消息引擎；Executors 先停止并 join 所有执行器，再清空其指针，避免在途 IO 完成访问已清空的 Main。第三处在 FlightHubSdkImpl::shutdown 中先停止并等待 Main/Compute/IO 线程，再销毁业务对象；避免查询回调读取已释放的设备列表。无业务协议修改。原 checkout 保持不变。

当前原生绑定 API 版本为 4。新版加载器拒绝 API 3 及更早的库，避免沿用缺少帧预算和安全关闭修复的二进制。

## 尚未证明的范围

全量方法对照使用官方 Java 包装层和 Node 原生接口测试替身，证明转换及调用约定，不证明所有设备动作。实机验收、不同型号、持续 RTC/DRC 视频、多日运行、所有故障恢复和完全内存安全仍需专项验证。

项目状态为候选版。SDK 与 Skeleton Demo 的验收范围分别记录；Demo 路由数量不代表完整生产后台已经验收。
